# sorenavi — 技術の確かめ

実機・実地で技術を確かめた方法と結果を書く。

## 説明書をどう手に入れるか（2026-10-30）

### 確かめたかったこと

型番を入れるか、型番ラベルの写真を送るだけで、アプリが公式の説明書を探して取ってこられるか。

### 確かめ方

- 主なメーカー（パナソニック・日立・シャープ・東芝ライフスタイル・三菱電機・ダイキン）のサイトのrobots.txtを読んだ
- 日立（BW-V100K）とパナソニック（WH3101WP）の説明書のページを開き、PDFの置き場所と利用条件を読んだ
- 同じ2つの型番を、ふつうのWeb検索で調べた
- ClaudeのAPIのPDFの渡し方を、公式の文書（[PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)）で読んだ

### 結果

- **型番から説明書を見つける**
  - 日立：説明書のページのアドレスに型番が入る（`/support/{種類}/item/{型番}/manual.html`）。種類の部分も要る。PDFのファイル名は型番と別の名前
  - パナソニック：製品のページのアドレスに型番が入る（`/{種類}/products/{型番}/support.html`）。PDFのアドレスは数字の羅列で、型番からは決まらない
  - シャープ・ダイキン：公式サイトの中に型番の検索がある、という情報までは確かめた（中の仕組みは未確認）
  - ふつうのWeb検索では、2つとも公式の説明書が出てこなかった（別の製品や、メーカー以外の説明書サイトが出た）
- **自動で取ってきてよいか**
  - パナソニック：robots.txtで、説明書のPDF（`/content/dam/panasonic/jp/ja/pim-assets/support/manual/*.pdf`）を断っている。利用条件は「許可なく写す・変える・送ることはできない。印刷は1部まで」
  - 日立：robots.txtは無い。利用条件は「非営利の目的で、個人的に使う場合に限り、写してよい」。条件に同意してから見る仕組み
  - シャープ・東芝ライフスタイル・三菱電機・ダイキン：robots.txtに、説明書を断る書き方は無かった（利用条件までは見ていない）
- **ClaudeのAPIへの渡し方**
  - PDFは、リンクのまま渡せる（Anthropic側が取りに行く）。ほかに、ファイルの中身を送る形と、先にアップロードしておく形（Files API）がある
  - 上限は、1回のリクエストで128MB・600ページ（使うモデルの読める量が100万トークン未満なら100ページ）
  - 各ページを文字と画像の両方として読む。3ページで約7,000トークン

### 決めたこと

- 型番や写真から自動で取ってくる形は、今回はやらない（メーカーごとに別の作りが要り、サイトが変わると壊れる。パナソニックは自動での取得を断っている）
- 説明書は、利用者がメーカーの公式サイトでPDFのリンクをコピーして、アプリに貼る形にする

### まだ確かめていないこと

- リンクで渡した時に、Anthropic側が日立・パナソニックのPDFを実際に取れるか（APIの鍵がまだ無いため）。作り始めの最初のタスクで試し、取れないメーカーがあれば、そのメーカーの分だけPDFを入れる機能を足す
- 型番ラベルの写真から、AIが型番を正しく読めるか（今回は写真での登録をやらないので、後回し）
